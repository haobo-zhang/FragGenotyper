## 继承的 1.8.1 导入与启动修复

1.8.0、1.8.1、1.8.2 和原始输入文件均保留；旧应用不会自动获得 1.8.3 的主题修复。

- 启动时先显示加载窗口，再在后台加载分析和绘图组件。窗口显示当前组件、进度、耗时；加载失败会保留可复制的错误。可取消启动，正在加载的单个组件会安全结束后退出。
- 表型和独立分型表的读取、列识别、样本匹配和分组计数改为后台执行，进度可见且可取消。失败或取消保留导入前的数据和结果。导入后修改列映射或性状，也通过后台更新计数。
- 默认比较不再预先创建全部两两比较的隐藏列表。自定义列表仅在需要时生成；候选超过 5000 对时提示缩小所选组或使用参考组模式。这是界面候选列表的限制，不会偷偷截断实际检验或改变 BH 校正范围。
- 自动识别明确的无表头两列/三列表型文本。对本次提供的三列 `FID IID phenotype` 文件，保留第一行样本，自动使用第二列样本 ID 和第三列性状。歧义格式仍建议提供表头。
- 在可写位置持久缓存绘图字体，并修正打包工具强制改用临时缓存的行为，减少重复启动时的字体扫描。首次建立字体缓存仍可能需要十余秒，加载窗口会持续显示进度。

本机实测：`FibLen_BLUP.pheno.tsv` 实为**空格分隔、无表头**；`FibLen_Blup.phe.csv` 为带表头 CSV。两份文件均为 3840 个样本、3707 个有限数值，按样本匹配后的数值和缺失一致。新版纯读取约 0.002–0.007 秒；配合模拟的 3840 个不同分组，后台导入到界面更新约 0.13 秒。此为本机一次测量，不能代表所有机器和数据规模；模拟分组用于压力测试，不是用户真实分型结果。

旧界面即使未显示自定义比较，也创建两个完整比较列表。200 个组时就各有 19900 项，该步骤占导入后界面更新约 93%；3840 个组理论上需创建约 1474 万个列表项。修复后默认列表均为 0 项。测量记录见 `examples/import_profile_before.json`、`examples/table_io_profile.json`。

1.8.1 上一版 Mac 成品原生启动复测：第一次建立字体缓存时主窗口约 17.4 秒就绪（字体扫描约 13.2 秒），同一应用第二次约 3.0 秒就绪（字体加载约 0.005 秒）。加载窗口在后台导入组件期间持续显示；显式设置的字体缓存路径也已验证可保留。该计时从启动控制器创建开始，不包括系统启动应用前的等待。本版 1.8.3 也已重新验证成品启动，记录见 `examples/packaged_startup_summary.json`。

性能边界：打开保存项目仍同步读取输入；分析完成后的绘图和结果表填充仍在主线程。极大项目或大量比较的结果显示仍可能耗时。本次优化针对常规表格导入、导入后设置更新和启动加载。

## GUI 流程

左侧有三个工作区：

1. **片段分型**：选择 VCF/VCF.GZ 或项目约定的 GT 表，选择相似度或 K-means，查看分组、热图、选 K 诊断，导出结果。
2. **表型比较**：按“数据 → 比较 → 绘图”三个设置页操作；右侧显示箱线图、检验结果和描述统计。
3. **变异筛选**：设置样本、区间、MAF 和缺失率，生成新 VCF，并查看筛选 QC。

分型成功后，`Sample,Genotype` 结果会自动送入“表型比较”，可直接加载表型表继续分析。也可独立加载之前的分型结果，或仅包含分组和性状的合并表。

长任务在后台执行，界面显示进度并可请求取消。K-means、SciPy 等库函数运行期间会等待当前计算完成后取消；关闭窗口也采用相同的安全停止方式。

## 片段分型的修正

- 按 VCF `FORMAT` 中的 `GT` 位置读取，而不是假定样本字段的第一项总是 GT。
- 仅将明确的二倍体二等位 SNP 转换为 ALT 剂量 `0/1/2`。完整缺失、部分缺失、未支持 GT、非二倍体和未支持变异按 NaN 处理，并记录 QC；热图显示为灰色。
- 相似度仅使用双方都有有效 GT 的位点；共同缺失不增加相似度。可设置“最少共同有效 SNP”，默认 1，建议根据片段位点量和缺失程度调整。
- 保留两种相似度策略的区别：矩阵法以未分组的首样本为中心；逐一法允许与已有组任一成员匹配。两者仍受样本顺序影响，GUI 有说明。
- K-means 对每个 SNP 按有效样本均值填补，剔除全缺失 SNP；全缺失样本拒绝分型，并显示样本名。填补数量、剔除数量可导出 QC。
- 自动选 K 与最终 K-means 使用同一套“样本 × 位点”矩阵及预处理。K 上限受样本数和不同向量数约束，避免小数据非法 K。推荐值取有效 silhouette 最大者；无有效评分时保守推荐 1。候选表和 SSE/silhouette 图供人工评估，推荐值不是已验证的真实分组数。
- 聚类树采用平均连接及欧氏距离，使用同样的缺失处理；它是聚类树，不是拟合的进化树。

分型中的 `0|1`、`1|0` 均转换为剂量 1，因此该模块得到的是未定相的多位点基因型模式分组，不重建相位。表型模块也可直接接收外部已确定的单倍型标签。

## 表型比较：数据

支持 UTF-8 的 CSV、制表符或空格分隔文本，保留 `001` 等字符串样本和分组标签。

**两张表**：分型表选样本列、分组列；表型表选样本列，勾选一个或多个性状。两张表按非空样本名一对一匹配，重复样本名会报错，避免合并产生伪重复。

```csv
Sample,Genotype
001,Hap1
002,Hap1
003,Hap2
004,Hap2
```

```csv
Sample,Length,Strength
001,28.5,30.1
002,29.0,31.2
003,32.1,33.0
004,33.0,32.8
```

**一张合并表**：选择分组列并勾选性状，不要求存在 Sample 列。例如 `Hap,Yolo`。无样本名时自动生成行 ID。

空分组、缺失、非数值和无穷表型会剔除。页面报告匹配和清洗数量；分组列表的 n 基于首个所选性状，其他性状在运行时各自清洗，结果中的 n 才是对应性状的实际样本数。即使首个性状某组 n=0，也保留该组供其他性状选择。

## 表型比较：检验与图形

- 勾选参与分析的单倍型，支持上移/下移改变组顺序。
- 比较模式包括“所选组两两比较”“与参考单倍型比较”“自定义比较”。自定义列表决定实际执行哪些检验。
- 使用双侧 Welch 独立样本 t 检验。每个所选组至少需要两个有效值；某性状样本不足时记录该性状失败，其余性状继续。
- 结果包含各组 n、均值、均值差、标准误、Welch 自由度、95% CI、原始 P、校正 P、星号和状态。均值差为 Group1−Group2；参考模式中 Group1 固定为参考组。
- 可选择 BH（默认）或原始 P。BH 的家族可选“每个性状分别校正”，或“本次全部成功性状的全部有限 P 一起校正”。失败性状及未定义检验不贡献虚构 P 值，失败原因完整导出。校正范围不涵盖历史运行或其他未纳入的性状。
- **95% CI 是逐比较、未作多重比较校正的 Welch 区间**，不等于同时置信区间；星号依据本次选择的原始/校正 P，二者口径在界面和导出参数中说明。
- 两组均为相同常量时，Welch 无定义，P 和 CI 保留缺失、图中标 `n/a`；不同常量保留 SciPy 极限检验结果但不提供可信零宽 CI。统计表明确标记状态。
- 绘图保留空心箱体、抖动散点、均值菱形及样本数。可改标题、纵轴单位、字号、点大小、配色、分组显示名称与颜色，隐藏散点或均值。
- 标注可选 P+星号、仅 P、仅星号；可显示全部、仅显著、指定比较或不画括号。**图形筛选不删除统计结果，也不重算校正家族。**
- 右侧工具栏支持平移、缩放与恢复。图形设置改变后直接重绘，检验设置改变后清除旧结果，需重新运行。

## 保存项目、导出结果

“保存项目”写入普通 JSON：输入路径、列映射、所选性状、组与顺序、比较、参考组、校正及图形配置。文件路径相对于项目文件保存，便于连同数据移动；直接接收的当前分型表以普通记录嵌入 JSON。项目不执行脚本或 pickle，不存储可恢复的旧统计结果，打开后需重新运行。

“导出本次分析”选择父目录后，创建新的 `FragGenotyper_analysis` 文件夹，若已存在则自动编号，不覆盖旧导出。每个成功性状生成：

| 文件 | 内容 |
| --- | --- |
| `001_性状名.png` / `.pdf` | 300 dpi PNG 和 PDF |
| `001_性状名_tests.csv` | 完整检验结果与未校正 95% CI |
| `001_性状名_summary.csv` | n、均值、标准差、中位数、范围 |
| `001_性状名_data.csv` | 实际参与检验的所选数据 |
| `all_tests.csv` | 本次所有成功性状的检验结果 |
| `metadata.json` | 来源、列、比较、校正、清洗、图形设置和失败清单 |

导出先写入临时目录，完整成功后才发布结果文件夹；取消或失败会清理临时产物。

## 变异筛选

坐标从 1 开始，区间包含两端；样本列表可按行、逗号或空白输入。仅保留明确二等位 SNP，MAF 和样本缺失率在保留样本内重算，部分缺失 GT 按整个样本缺失计。已有 AC/AN/AF/NS INFO 值会更新，失效的 MLEAC/MLEAF 移除。输入和输出路径不得相同。

`.vcf.gz` 是真实的普通 gzip，**不是 BGZF，不能直接建立 tabix 索引**；如需索引应另外用 bgzip 重压缩。本模块筛选输入为 VCF/VCF.GZ。
